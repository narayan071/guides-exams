Ch 1: UNIX / Linux Architecture, Boot Process & Shells High-Yield

Start Here UNIX originated at AT&T Bell Labs (1969) (Ken Thompson & Dennis Ritchie; rewritten in C in 1973). GNU Project (1983, Richard Stallman) built open tools; Linux kernel (1991, Linus Torvalds) is monotonic/monolithic (modular loadable kernel modules .ko). Standards compliance is defined by POSIX (IEEE 1003).

Layered OS Architecture & Kernel Types

  • Execution RingsHardware → Kernel (Ring 0) → Syscalls → Shell → User Apps (Ring 3).
  • Kernel RoleProcess scheduling, virtual memory, VFS, device drivers, IPC & syscalls.
  • Shell RoleCommand-line interpreter & scripting engine; parses, expands, and forks commands.
  • Monolithic KernelLinux/UNIX — drivers run inside kernel space (fast IPC, loadable lsmod/modprobe).
  • Kernel Threads / SpaceApps enter Kernel Mode only via software interrupt (syscall / trap).
  • Terminal vs ShellTerminal/TTY (/dev/pts/0) handles I/O display; Shell interprets commands.

Linux Boot Sequence (Exact Exam Order)

2. Partition / Stage 1MBR vs GPTMBR (512 bytes): 446 B boot code + 64 B (4 primary × 16 B) partition table + 2 B magic (0x55AA); 2 TB max. GPT: 128 partitions, >2 TB, CRC32 checksum.

Inodes, Timestamps & Hard Link vs Soft (Symbolic) Link

What an Inode Stores vs Does NOT Store

  • Stored in Inode (Index Node, seen via stat / ls -i): File type, permissions, UID/GID, byte size, link count, atime/mtime/ctime, pointers to disk data blocks.
  • NOT Stored in Inode: Filename (stored in parent directory mapping name → inode#) and actual file bytes.
  • Why mv on same partition is O(1): Only rewrites parent directory entry; inode# stays identical. Copying (cp) creates a new inode.
  • 3 Timestamps: atime (last read), mtime (content change), ctime (inode metadata change like chmod/chown/ln).

Hard Link vs Symbolic (Soft) Link

  • Hard Link (ln orig hard): Shares the exact same inode#; increments link count. Deleting orig keeps data intact until link count drops to 0 (rm just unlinks a name).
  • Hard Link Limits: Cannot span different filesystems/partitions; cannot link directories (prevents tree loops).
  • Soft Link (ln -s orig sym): Separate inode holding the target path string (lrwxrwxrwx). Can cross filesystems & link directories. Deleting orig leaves a dangling/broken symlink.
Scale 2 Ops Scenario: "No space left on device" when df -h shows 30% Free! Each file consumes 1 inode. Millions of tiny 1 KB temp/session files can exhaust 100% of a filesystem's fixed inodes while gigabytes of blocks stay unused. Diagnose with df -i!

Start Here UID 0 is always root (superuser — bypasses normal permission checks). System accounts typically use UIDs 1–999; normal users start at 1000. Always validate sudo edits with visudo so syntax errors don't lock out admin access!

Octal / Symbolic chmod, Ownership & Special Permission Bits

Common Numeric & Symbolic Modes

  • 755 (rwxr-xr-x): Executable scripts, web root dirs.
  • 644 (rw-r--r--): Standard config & text files.
  • 600 (rw-------): SSH private keys (~/.ssh/id_ed25519 — SSH refuses key if group/others can read!).
  • Symbolic syntax: u (user), g (group), o (others), a (all); operators + (add), - (remove), = (exact). E.g. chmod u+x,go-w script.sh.
  • Ownership: chown user:group file (-R recursive; only root can change file owner user). chgrp group file changes only group.

Special Bits: SUID (4), SGID (2), Sticky Bit (1)

  • SUID (4xxx / chmod u+s): Runs executable with file owner's effective UID (e.g., /usr/bin/passwd shows -rwsr-xr-x so normal users can update root-owned /etc/shadow).
  • SGID (2xxx / chmod g+s): On binary → runs as file's group; on directory → newly created files inherit the directory's group (team collaboration dirs!).
  • Sticky Bit (1xxx / chmod +t): On shared dirs like /tmp (drwxrwxrwt) → only the file owner, dir owner, or root can delete/rename files inside!
  • Upper vs Lowercase Trap: rws/rwt = underlying x bit is set; uppercase rwS/rwT = special bit set WITHOUT underlying x!

umask Calculation (File Creation Mask)

  • Base Defaults: New directories start at 777; new regular files start at 666 (never auto-executable by default for security!).
  • Rule: Effective Mode = Base_Mode & (~umask) (clears bits set in umask).
  • Examples: umask 022 (default root/standard) → File 644, Dir 755. umask 027 → File 640, Dir 750. umask 077 (strict private) → File 600, Dir 700.
Odd-Digit umask Numerical Trap (Scale 2 Classic!) NEVER use blind decimal subtraction for files! With umask 027: Dir = 777 - 027 = 750, but for a File (base 666), 7 (111) masks 6 (110) down to 0 (---), NOT -1 or borrow! Correct file permission for umask 027 is 640 (rw-r-----). Even more subtle: umask 011 on base 666 removes NO bits (since 6 has no execute bit 1!), leaving 666!

Ch 5: Process Management, Signals, System Monitoring, Cron & Networking Ops

Start Here In Scale 2 IT Officer production scenarios, expect questions on killing hung vs stuck processes, interpreting ps/top states (especially Zombie vs Orphan and Uninterruptible D), free RAM vs page cache, open deleted files filling disk, systemctl lifecycle, and cron scheduling!

Process Creation, States & UNIX Signals

Syscalls & ps / top Process States

  • Lifecycle: fork() clones parent returning child PID to parent and 0 to child; exec() replaces child's memory image with new binary; wait() collects child's exit code.
  • R (Running/Runnable) • S (Interruptible Sleep waiting for event) • T (Stopped by job control/debugger).
  • D (Uninterruptible Sleep): Blocked inside kernel I/O (faulty NFS/disk) — even kill -9 cannot terminate it until kernel I/O returns!
  • Z (Zombie / Defunct): Child finished executing, exit status still sits in process table because parent hasn't called wait() yet. You cannot kill -9 a zombie (it's already dead!); signal or restart its parent (PPID)!
  • Orphan Process: Still-running child whose parent died; automatically adopted (re-parented) by PID 1 (systemd).

Key Signals (kill -l) & Job Control

  • 1 SIGHUP: Terminal hangup — tells daemons (Nginx, sshd) to reload config gracefully.
  • 2 SIGINT: Ctrl+C interrupt from keyboard (catchable).
  • 15 SIGTERM: Default signal of kill <pid>! Allows graceful cleanup, closing DB connections & temp files.
  • 9 SIGKILL: Immediate kernel termination — cannot be caught, blocked, or ignored (last resort!).
  • 19 SIGSTOP (Ctrl+Z sends 20 SIGTSTP) & 18 SIGCONT: Pause / resume process.
  • Job Control: cmd & (background), jobs, fg %1, bg %1, nohup ./batch.sh & (ignores SIGHUP after SSH disconnect, writes nohup.out).
  • CPU Priority (nice): Range -20 (highest) to +19 (lowest); default 0. Regular users can only make processes nicer (positive values); only root can use negative nice!

Ch 6: I/O Redirection, Pipes, Wildcards (Globs vs Regex) & Quoting

Start Here Redirection is parsed left-to-right by the shell before the command executes. Understanding file descriptors 0, 1, 2, pipe subshells, and quote strength prevents 80% of Bash production bugs and exam output traps.

Standard File Descriptors & Redirection Patterns

FD / OperatorMeaning & BehaviorExam Example / Trap
0 (<)stdin — Standard Input from filemysql db < dump.sql • cat << 'EOF' (Here-doc, quotes disable $ expansion!) • <<< "str" (Here-string).
1 (>, >>)stdout — Overwrite (>) / Append (>>)Trap: Shell truncates target of > before running command (sort f > f wipes f empty! Use -o f or temp file!).
2 (2>, 2>>)stderr — Diagnostic / Error Outputfind / -name conf 2>/dev/null discards Permission Denied noise cleanly.

Pipes (|), tee, xargs & Chaining Operators

  • Pipe (cmd1 | cmd2)Connects stdout of cmd1 → stdin of cmd2 (NOT stderr unless 2>&1 | or |&!). Each stage runs in a subshell.
  • tee (T-splitter)./deploy.sh | tee -a deploy.log prints output to screen AND writes to file (-a appends instead of overwriting!).
  • xargs (Stdin → Args)Commands like rm, cp, echo ignore stdin! find . -name "*.tmp" -print0 | xargs -0 rm safely converts null-delimited paths into arguments (handles filenames with spaces!).
  • Chaining (; && ||)a ; b runs b always | a && b runs b only if a succeeds ($? == 0) | a || b runs b only if a fails ($? != 0).

Quoting Hierarchy & Shell Wildcards (Globs) vs Regex

Single Quote vs Double Quote vs Backslash

  • No Quotes: Expands variables, command substitution, globs (*), AND splits words on whitespace ($IFS).
  • Double Quotes ("..."): Keeps spaces intact (prevents word splitting & globbing!), while STILL expanding $VAR, $(cmd), and \. Always quote variables: "$file"!
  • Single Quotes ('...'): Literal mode — treats every character literally (no $VAR, no *, no escape — cannot even contain ' inside!).
  • Backslash (\): Escapes the single character right after it (or splits a long command across lines at EOL).

Shell Globbing vs Regular Expressions (Trap!)

  • Shell Globs (Filename expansion): * = 0+ any chars; ? = exactly 1 char; [abc] / [!0-9] = 1 char class; {a,b} = brace expansion (generates strings even if files don't exist: mkdir -p logs/{2025,2026}).
  • Hidden Files Trap: ls * does NOT match dotfiles (.bashrc)!
  • Regex Trap (grep, sed, awk): Inside regex, . = any 1 char (NOT literal dot!), * = 0+ copies of preceding atom (a*, NOT wildcard!), + = 1+ (needs -E), ^ = start of line, $ = end of line!

Ch 7: Bash Shell Scripting — Variables, Conditionals, Loops & Production Patterns Implementation

Start Here Start every portable script with #!/usr/bin/env bash (or #!/bin/bash). Running ./script.sh executes inside a subshell (child variables never leak back to caller!); running source script.sh or . script.sh executes in the current shell!

Variables, Assignments & Exit Status

  • No Spaces Around = (Classic Syntax Trap!): Write HOST="10.0.1.5" — writing HOST = "10.0.1.5" runs command HOST with argument = (fails with HOST: command not found)!
  • export & Scope: Unexported variable X=5 stays local to current shell; export X=5 passes it down to child processes/scripts. Read-only: readonly PI=3.14 or declare -r; integer: declare -i n=10.
  • Exit Codes ($?): 0 = success (truthy in Bash if — opposite of C/Python booleans!); 1 = general error; 2 = misuse of shell builtin; 126 = not executable / permission denied; 127 = command not found; 128 + N = killed by signal N (e.g., 137 = 128 + 9 killed by SIGKILL / OOM!).

Part A: Core Concept & Command Mastery (Q1–Q12)

Q1 During Linux boot, which step immediately follows GRUB2 loading vmlinuz and initramfs, and what PID does it always receive?
A) fsck, PID 0   B) systemd/init, PID 1   C) login, PID 1   D) bash, PID 2   E) BIOS POST, PID 0
Answer: B) systemd / init, PID 1.
Once the kernel extracts initramfs drivers and mounts the root filesystem /, it executes /sbin/init (symlinked to systemd), which is always PID 1 and adopts orphan processes. (PID 0 is the internal kernel scheduler/swapper task, not user-space).
Q2 Which piece of file information is NOT stored inside a Linux inode?
A) File permissions & UID   B) Data block pointers   C) Hard link count   D) Original filename   E) Timestamps (mtime/ctime)
Answer: D) Original filename.
Filenames live in the parent directory entry (mapping filename → inode#). Because filenames aren't in the inode, multiple hard links in different directories can point to the exact same inode under different names!
Q3 What happens to a hard link vs a symbolic (soft) link when the original target file is deleted with rm?
A) Both break immediately   B) Hard link still holds intact data; soft link breaks (dangling)   C) Soft link retains data; hard link breaks   D) rm is blocked until all soft links are removed   E) Kernel panics on next access
Answer: B) Hard link retains data; soft link breaks.
rm only removes one directory link and decrements the inode link count; file data persists until the link count reaches 0. A symlink stores only a path string, so deleting the target leaves it pointing at a missing path.
Q4 Which umask value causes newly created files to have 640 (rw-r-----) and new directories to have 750 (rwxr-x---)?
A) 022   B) 027   C) 077   D) 640   E) 137
Answer: B) 027.
Directory: 777 & ~027 = 750. File (base 666): 666 & ~027 = 640 (note the bit 1 in 7 masks execute bit, which files already lack, so 6 & ~7 = 0 — classic odd-umask trap!).
Q5 Which permission bit on /tmp (drwxrwxrwt) prevents User A from deleting a file created by User B inside the same directory?
A) SUID (4000)   B) SGID (2000)   C) Immutable flag (chattr +i)   D) Sticky Bit (1000)   E) Read-only group bit
Answer: D) Sticky Bit (1000 / chmod +t).
Even though /tmp has 777 write access for everyone, the Sticky Bit restricts deletion/renaming of entries inside it strictly to the file owner, directory owner, or root.
Q6 By default, what signal does kill 4512 send if no signal flag is specified?
A) SIGKILL (9)   B) SIGINT (2)   C) SIGHUP (1)   D) SIGTERM (15)   E) SIGSTOP (19)
Answer: D) SIGTERM (15).
SIGTERM (15) asks the process to shut down gracefully (saving state/closing sockets). SIGKILL (9) must be specified explicitly (kill -9 4512) and cannot be caught or ignored.
Q7 Which field in /etc/passwd indicates that the encrypted password hash is stored securely in /etc/shadow?
A) Field 1 (*)   B) Field 2 (x)   C) Field 3 (0)   D) Field 5 (GECOS)   E) Field 7 (/bin/false)
Answer: B) Field 2 (x).
Format: username:x:UID:GID:GECOS:home:shell. Putting x in field 2 instructs PAM/auth libraries to look up the actual password hash in root-protected /etc/shadow.
Q8 Which command safely monitors a live log file even after logrotate renames the old log and creates a fresh file at the same path?
A) tail -n app.log   B) tail -f app.log   C) tail -F app.log   D) head -f app.log   E) cat -f app.log
Answer: C) tail -F app.log.
-f tracks the open file descriptor (so after log rotation it follows the renamed app.log.1!), whereas -F (--follow=name --retry) re-opens the filename whenever a new file replaces it.
Q9 Which crontab entry runs a backup script at 02:30 AM every Monday through Friday?
A) 2 30 * * 1-5   B) 30 2 * * 1-5   C) 30 2 1-5 * *   D) * 2 30 * 1-5   E) 30 14 * * 1-5
Answer: B) 30 2 * * 1-5.
Cron order is always MIN HOUR DOM MON DOW. Option C runs on the 1st–5th day of every month instead of weekdays; Option A puts hour/minute swapped (invalid minute 30 in hour field).
Q10 In ls -l output, what do permissions starting with -rwsr-xr-x signify?
A) Sticky bit set on directory   B) SGID set without execute   C) SUID set WITH owner execute bit   D) SUID set WITHOUT owner execute bit   E) Symlink with executable flag
Answer: C) SUID set WITH owner execute bit.
Lowercase s in the owner triad (bits 1–3 after file type) means SUID (4000) + owner x. Uppercase S would mean SUID set without owner x.
Q11 Why does cut -d' ' -f4 file.txt often return the wrong column on aligned command output like ps or ls -l, and what tool handles it cleanly?
A) cut requires -c; use cat   B) cut treats each consecutive space as a separate empty field; use awk '{print $4}'   C) cut ignores field numbers >3; use grep   D) cut only works on root files; use tr   E) cut sorts alphabetically first; use sed
Answer: B) Use awk '{print $4}'.
cut -d' ' splits on every single space, so multiple padding spaces shift column numbers unpredictably. awk (and tr -s ' ') automatically treats runs of whitespace as a single delimiter.
Q12 Which modern Linux command replaces deprecated netstat -tulnp to display listening TCP/UDP sockets along with PIDs?
A) ip addr   B) ss -tulnp   C) dig -p   D) vmstat -n   E) route -n
Answer: B) ss -tulnp.
ss (Socket Statistics from iproute2) reads kernel socket info directly via netlink, making it much faster than parsing /proc/net via legacy netstat.

Part B: Scenario-Based Scale 2 IT Officer Questions (Q13–Q24)

Q13 · Scenario A banking app server alerts that df -h shows /var at 100% full, yet du -sh /var/* totals only 40% of the partition size. A teammate ran rm /var/log/cbs-huge.log 10 minutes ago. Why wasn't disk space freed, and how do you find & fix it cleanly?
A) Run mkfs.ext4 on /var   B) Run sync; kernel buffers delay delete by 1 hour   C) The running JVM/service still holds an open FD to the deleted inode; run lsof +L1 and gracefully reload/restart that service   D) Switch umask to 000   E) Create a hard link to /dev/null
Answer: C) Open FD to unlinked inode (lsof +L1).
Removing a filename only unlinks its directory entry; Linux does not reclaim disk blocks until both link count = 0 AND open file descriptors = 0. Identify the holding PID with lsof +L1 (or lsof | grep deleted) and restart/reload the daemon.
Q14 · Scenario On a Linux payment gateway, df -h shows 18 GB free, but writing even a 10-byte file fails with No space left on device. Which command diagnoses the bottleneck?
A) free -h   B) df -i   C) top -o %MEM   D) vmstat 1   E) ulimit -u
Answer: B) df -i (inode exhaustion).
Filesystems like ext4 allocate a fixed number of inodes at format time. Millions of tiny temp/session files can consume 100% of inodes before disk blocks fill up!
Q15 · Scenario In /opt/team (permissions drwxrwxr-x, no sticky bit), a file audit.csv has permissions 000 (---------) and is owned by root. Can non-root user raj (member of the directory's group) delete audit.csv with rm -f?
A) No, because audit.csv has 000   B) No, only root can delete root-owned files   C) Yes, because deleting a file modifies the parent directory where raj has w+x   D) Only if SUID is set on rm   E) Only via mv, never rm
Answer: C) Yes!
Classic Linux permissions trap: reading/editing a file checks the file's own bits, but creating, renaming, or unlinking (rm) checks w + x on the parent directory (since unlinking edits the directory table). Without the Sticky Bit, raj can delete it! (rm -i/default prompts because file isn't writable, whereas rm -f unlinks cleanly).
Q16 · Scenario An IT admin wants to run a batch script and save both standard output and errors into run.log. Which command succeeds?
A) ./batch.sh 2>&1 > run.log   B) ./batch.sh > run.log 2>&1   C) ./batch.sh > run.log | tee err.log   D) ./batch.sh 1> run.log 2> run.log   E) ./batch.sh << run.log
Answer: B) ./batch.sh > run.log 2>&1.
Redirection is evaluated left-to-right! In A, 2>&1 points stderr to the screen before stdout moves to run.log. In D, opening the same file independently twice causes fd1 and fd2 to overwrite each other's offsets! Option B (or Bash &> run.log) points both cleanly to the single open FD.
Q17 · Scenario A sysadmin runs find /tmp/cache -name "*.tmp" -type f | rm -f, expecting old temp files to vanish, yet nothing is deleted. Why, and what fixes it safely (even with spaces in filenames)?
A) Missing sudo   B) rm ignores stdin; pipe through -print0 | xargs -0 rm -f or use find ... -delete   C) Pipe sends stderr instead of stdout   D) -name must come after rm   E) find cannot search /tmp
Answer: B) rm does not read filenames from stdin.
rm expects filenames as positional command-line arguments. Use find ... -delete or find ... -print0 | xargs -0 rm -f (using null-byte separator prevents filenames containing spaces from breaking into two bogus arguments!).
Q18 · Scenario You updated /etc/nginx/nginx.conf on a live banking portal during peak hours. How do you test syntax and apply changes with zero downtime to existing active connections?
A) nginx -t && systemctl restart nginx   B) killall -9 nginx && nginx   C) nginx -t && systemctl reload nginx (or kill -HUP)   D) systemctl enable nginx   E) reboot
Answer: C) nginx -t && systemctl reload nginx.
nginx -t validates syntax before touching the live master process; reload (sending SIGHUP) spawns new worker processes with the new config while letting old workers finish active in-flight connections gracefully! restart drops active connections.
Q19 · Scenario A script env_init.sh defines and runs export API_ENV=prod. You execute ./env_init.sh, then type echo $API_ENV in your terminal and get an empty line. Why?
A) Missing $ before API_ENV=prod   B) ./env_init.sh spawned a child subshell; child exports cannot modify the parent shell's environment (use source ./env_init.sh)   C) Bash clears variables after script exit   D) export only works for integers   E) Missing shebang
Answer: B) Executed in a child subshell; use source ./env_init.sh (or . ./env_init.sh).
Environment variables flow strictly parent → child, never upward! To apply variable/directory changes inside your current interactive shell, source the file in-process.
Q20 · Scenario Top shows several processes in Z (Zombie) state and one process in D (Uninterruptible sleep) state tied to an unresponsive NFS mount. Even kill -9 fails on both. Why?
A) Only UID 1 can kill Z and D   B) Zombies are already dead awaiting parent wait() (kill/fix PPID); D-state processes are blocked inside kernel I/O and ignore signals until I/O resolves   C) Use kill -15 instead of -9   D) SELinux blocks root signals   E) Rebooting makes zombies permanent
Answer: B) Zombies are already dead; D-state is mid-kernel-I/O.
kill -9 destroys live user-space processes: zombies already exited (reaped when their parent handles SIGCHLD/exits), while D-state processes don't return from the kernel syscall to inspect pending signals until the storage/NFS I/O returns or times out.
Q21 · Scenario On a Linux production DB box (32 GB RAM), free -h shows: total 32G | used 8G | free 1.2G | buff/cache 22.8G | available 23.5G. Should you raise a critical low-memory alert?
A) Yes — only 1.2G free remains (<5%)   B) Yes — buff/cache cannot be reclaimed   C) No — Linux proactively uses spare RAM as disk page cache and reclaims it automatically; real headroom is available (23.5G)   D) Yes — run kill -9 on kernel cache   E) Only Swap matters
Answer: C) No — healthy system with ~23.5 GB available.
"Unused RAM is wasted RAM" in Linux: clean filesystem caches in buff/cache are evicted instantaneously whenever applications request memory. Always alert on available RAM & swap thrashing, not raw free!
Q22 · Scenario You run usermod -G docker anita intending to add developer anita (previously in sudo,developers) to the docker group. Next day, anita reports losing sudo access! Why?
A) docker forbids sudo   B) Missing -a (append): usermod -G without -a overwrites all existing supplementary groups!   C) usermod deletes the user account   D) Need chmod +s /bin/sudo   E) Group changes require BIOS reset
Answer: B) Forgot -a (usermod -aG docker anita).
Always combine -a with -G when adding a user to an extra group, otherwise their secondary group list is replaced solely with the newly specified list!
Q23 · Scenario An automation script has cron schedule: 0 4 1-7 * 0 /opt/jobs/weekly_monthly.sh. What happens across a month?
A) Runs ONLY on the first Sunday of the month   B) Never runs because syntax is invalid   C) Runs every day from the 1st–7th PLUS every Sunday of the month (logical OR trap!)   D) Runs every 4 hours on Sunday   E) Runs once per year
Answer: C) Logical OR between Day-of-Month and Day-of-Week!
In Vixie cron, when both DOM and DOW are non-wildcard (!= *), cron fires if either matches. To run strictly on the first Sunday of a month, trigger daily/DOM 1-7 in cron and guard with [ "$(date +%u)" -eq 7 ] && ... inside the command!
Q24 · Scenario An SSH client refuses a private key ~/.ssh/prod_key with error UNPROTECTED PRIVATE KEY FILE! Permissions 0644 are too open. What exact command fixes it?
A) chmod 777 ~/.ssh/prod_key   B) chmod 600 ~/.ssh/prod_key (or 400)   C) chmod +t ~/.ssh/prod_key   D) chmod 755 ~/.ssh/prod_key   E) umask 000
Answer: B) chmod 600 ~/.ssh/prod_key (or 400).
OpenSSH strictly rejects private keys accessible by group or others; only the key owner may have read/write access (and ~/.ssh itself is normally 700).

Part C: Output Prediction & Bash Syntax Traps (Q25–Q32)

Q25 · Output Trap What is the output and side effect of this Bash command?
if [ 10 > 2 ]; then echo "YES"; else echo "NO"; fi
A) Prints YES, no side effect   B) Prints NO, because 10 > 2 is lexicographically false   C) Syntax error   D) Prints YES AND silently creates an empty file named 2!   E) Loops infinitely
Answer: D) Prints YES and creates empty file 2!
Inside single brackets [ ... ], > is NOT greater-than — Bash interprets > 2 as stdout redirection to file 2, leaving [ 10 ] (a non-empty string, which is true!). Always use [ 10 -gt 2 ] or (( 10 > 2 )).
Q26 · Output Trap Given BANK="RRB", what does echo '$BANK' "$BANK" \$BANK print?
A) RRB RRB RRB   B) $BANK RRB $BANK   C) 'RRB' "RRB" $BANK   D) $BANK $BANK RRB   E) Syntax error
Answer: B) $BANK RRB $BANK.
Single quotes '$BANK' keep $BANK literal; double quotes "$BANK" expand variables to RRB; backslash \$BANK escapes $ so it prints literally!
Q27 · Output Trap You run script ./check.sh "hello world" 2026 where check.sh runs:
echo "$# $(for x in "$*"; do echo "[$x]"; done) | $(for x in "$@"; do echo "[$x]"; done)"
What does $# equal, and how many bracketed items do "$*" vs "$@" emit?
A) 3; 1 and 3   B) 2; 1 item ([hello world 2026]) and 2 items ([hello world], [2026])   C) 2; 2 items and 1 item   D) 3; 3 and 3   E) 1; 1 and 2
Answer: B) $# = 2; "$*" emits 1 combined string; "$@" preserves 2 distinct arguments!
"hello world" is quoted as 1 arg and 2026 as arg #2 ($# = 2). Always wrap "$@" in scripts forwarding user arguments!
Q28 · Output Trap File nums.txt has lines: apple, banana, apple. What does uniq -c nums.txt output (WITHOUT sort first)?
A) 2 apple and 1 banana   B) Three lines: 1 apple, 1 banana, 1 apple   C) 3   D) Empty output   E) Error: file not sorted
Answer: B) 1 apple, 1 banana, 1 apple.
uniq inspects only adjacent lines and does NOT sort or error on unsorted input! Always pipe sort nums.txt | uniq -c to aggregate counts properly.
Q29 · Output Trap What does echo "A B C" | false && echo "OK" || echo "FAIL" print, and why?
A) OK   B) A B C then OK   C) FAIL   D) Both OK and FAIL   E) Nothing
Answer: C) FAIL.
In a pipeline, exit status $? is the exit code of the last command in the pipeline (unless pipefail is active; here false is last anyway → exit 1). So && echo "OK" skips, and || echo "FAIL" executes!
Q30 · Output Trap What does echo "err err" | sed 's/err/ok/' print?
A) ok ok   B) ok err   C) err ok   D) Unchanged err err   E) Syntax error
Answer: B) ok err.
Without the global flag g (s/err/ok/g), sed replaces only the first match on each line!
Q31 · Script Bug Why does this script snippet fail when invoked?
COUNT = 0
COUNT=$((COUNT + 1))
A) Missing $ on left side of COUNT=   B) Missing let   C) Spaces around = make Bash try executing command COUNT with arguments = and 0   D) Integers must be quoted   E) Missing semicolons
Answer: C) Spaces around =!
Variable assignment in Bash strictly requires no whitespace around = (COUNT=0). Otherwise Bash executes COUNT as a command!
Q32 · Output Trap Inside data.txt, line 1 is 10,20,30 and line 2 is 5,15,25. What does awk -F',' 'BEGIN{t=0} {t+=$2} END{print NR, t}' data.txt print?
A) 2 35   B) 3 35   C) 2 15   D) 1 20   E) 2 105
Answer: A) 2 35.
-F',' splits by comma; $2 is column 2 (20 + 15 = 35); in the END block, NR holds total records processed (2 lines). Prints 2 35!
