Ch 2: Hardware, CPU, Ports, Audio Jacks & Keyboard Keys

Start Here A CPU executes Fetch–Decode–Execute inside its Core(s), storing ALU results in the Accumulator. Know all legacy & modern ports (SATA, PATA, AGP, Parallel, HDMI, USB), 3.5mm audio jack colors, and keyboard key categories (Toggle, Modifier, Sticky).

CPU, Registers, Buses & Logic Gates

  • CPU Core & Cycle: Basic computation unit = Core (contains ALU + Control Unit [CU] + Registers). Instruction Cycle: Fetch → Decode → Execute → Store.
  • Key CPU Registers (Fastest Memory): Register = group of flip-flops. Accumulator (AC) stores ALU results | PC (Program Counter — next instruction address) | IR (Instruction Register — current instruction) | MAR / MDR (Memory Address / Data Register).
  • System Buses: Data Bus (bidirectional) | Address Bus (unidirectional, determines max addressable RAM) | Control Bus (bidirectional timing/control signals).
  • Universal Logic Gates: NAND and NOR (can build any Boolean function). Basic gates: AND, OR, NOT; Derived: XOR, XNOR.
  • Firmware, POST & SMPS: Firmware = hardware + software in ROM (e.g., BIOS / UEFI — runs POST [Power-On Self-Test] during boot). SMPS = Switch Mode Power Supply (AC → DC).
  • Adapters, Encoders & Terminals: Adapter changes a connector configuration / bridges interfaces; Peripheral Card puts info in/out; Plug & Play (PnP) auto-detects devices. Encoder converts data into another code system; Bit Manipulation modifies bits shorter than a word; Call-Directing Code = 2–3 char teletypewriter activation code. Dumb Terminal: Only keyboard & screen (no local processing).

Speed Hierarchy (Fastest → Slowest): Registers > L1/L2/L3 Cache > Main RAM > SSD > HDD > Optical > Magnetic Tape.

Secondary Storage (Auxiliary Memory), Optical, RAID & HDD Timing

  • Disk Formatting: Dividing a magnetic disk into concentric Tracks & pie-slice Sectors (cluster = group of sectors).
  • HDD Access Time Formula: Access Time = Seek Time + Rotational Latency + Transfer Time. (Seek Time = move head to track; Rotational Latency = wait for sector to spin under head).
  • Optical Discs (Pits & Lands, 12 cm): CD = 700 MB (CD-ROM = Read-Only; WORM = Write Once, Read Many [CD-R]; CD-RW = ReWritable) | DVD = 4.7 GB (single) / 8.5 GB (dual) | Blu-ray = 25 GB / 50 GB.
  • Backup Types (2025 PYQ): Full (entire dataset) | Differential (changes since last Full backup) | Incremental (changes since the most recent backup of ANY type — fastest backup, slowest restore).
  • RAID Levels: RAID 0 (Striping — speed, no redundancy) | RAID 1 (Mirroring — 100% fault tolerance) | RAID 5 (Striping with distributed parity, min 3 disks) | RAID 10 (Mirror + Stripe).
  • Floppy Disks (IBM): 3.5" = 1.44 MB | 5.25" = 360 KB–1.2 MB | 8" = 80 KB–1.2 MB.

Number Systems, ASCII, Unicode & Complements

  • Character Codes: ASCII = 7-bit (128 chars); Extended ASCII (EASCII) = 8-bit (256 chars); Unicode (UTF-8 / UTF-16) = universal encoding (UTF-8 uses 1–4 bytes, ASCII-compatible).
  • Conversions: Any base → Decimal (positional powers: (1101)₂ = 13, (1F)₁₆ = 31); Dec → Bin (divide by 2, bottom-up: (45)₁₀ = 101101); Bin ↔ Oct/Hex (group by 3 / 4: 110101 → (65)₈ / (35)₁₆); Dec Fraction → Bin (multiply by 2, top-down: 0.625 → .101); Bin Fraction → Dec ((101.101)₂ = 5.625).
  • Complements, BCD, Gray & Hamming Codes: 1's = flip bits; 2's = scan right-to-left, keep up to first 1, flip left bits. BCD = 4-bit per decimal digit (94 → 1001 0100). Gray Code = unit-distance code (1-bit change). Parity Bit = 1-bit error detection only; Hamming Code (R.W. Hamming) = error detection & correction. Character Set = full list of symbols recognized by hardware/OS.
  • 8-Bit Ranges: Unsigned = [0, 255]; Signed (2's comp) = [-128, +127].

Ch 4: Operating Systems, Booting, File Systems & Linux Commands

Start Here On booting, the OS is loaded into RAM. Know the Windows version sequence, open-source OS families, device drivers, NTFS vs FAT, and Linux CLI commands.

OS Basics, Process States, Scheduling & Deadlocks

OS Types, Booting & Process/Threads

  • OS Structure: Hardware → Kernel → Shell → Applications. OS loads into RAM on boot.
  • OS Types: Batch, Multiprogramming, Time-Sharing (Multitasking), Multiprocessing, Real-Time (Hard RTOS = strict deadline vs Soft RTOS), Distributed.
  • Process & PCB: 5 states: New → Ready → Running → Waiting → Terminated. PCB (Process Control Block) holds PID, state, PC, registers. Threads share code/data/heap, have own stack & registers (faster context switch).
  • Booting, Power & Storage: Cold vs Warm Boot; Sleep (RAM) vs Hibernate (Disk). Root Directory = main/top folder on a drive; Installation = copying/configuring software to disk; CPU Time = active processor time (excludes I/O wait). Device Driver controls hardware; Data Validation checks inputs (e.g., PIN) before entry.

CPU Scheduling, Deadlocks & Paging

  • CPU Scheduling: FCFS (Convoy effect) | SJF / SRTF (min avg waiting time, starvation risk) | Priority (starvation solved by Aging) | Round Robin (time quantum, pre-emptive). TAT = Completion − Arrival; WT = TAT − Burst.
  • 4 Coffman Deadlock Conditions (ALL 4 required): 1. Mutual Exclusion, 2. Hold & Wait, 3. No Preemption, 4. Circular Wait. Avoidance: Banker's Algorithm. Sync: Semaphore (wait/signal) & Mutex.
  • Memory & Page Replacement: Paging eliminates external fragmentation (uses TLB cache); Thrashing = excessive paging. Algorithms: FIFO (suffers Belady's Anomaly), Optimal, LRU.
  • Disk Scheduling: FCFS, SSTF, SCAN (elevator), C-SCAN.
  • OS Families, PDAs & Windows: Open-source = GNU/Linux, FreeBSD, Android, Chromium OS, OpenSolaris (Linux default browser = Firefox). PDA = Handheld OS. MS Windows achieved ~90%+ desktop OS share: ME → XP → Vista → 7 → 8/8.1 → 10 → 11 (Windows 10 reached End of Support on 14 Oct 2025; Windows 11 is sole supported desktop version in 2026).

Security Models, Cryptography & Defense Infrastructure

CIA Triad, MFA & Access Control

  • CIA Triad: Confidentiality (encryption, permissions), Integrity (hashing, checksums, digital signatures — detects tampering), Availability (backups, redundancy, anti-DDoS). Also Authentication & Non-repudiation.
  • Authentication Factors (MFA): Something you Know (password/PIN) • Have (OTP/token/smartcard) • Are (biometrics).
  • Access Control: DAC (Discretionary — owner sets permissions) | MAC (Mandatory — OS/admin sensitivity labels, strictest/military) | RBAC (Role-Based — permissions assigned per job role).

Cryptography, Hashing & PKI

  • Symmetric (Secret Key): Same key encrypts & decrypts (fast, bulk data). DES (56-bit effective key, 16 rounds, obsolete), 3DES, AES (AES-128 / AES-192 / AES-256 with 10 / 12 / 14 rounds, 128-bit block, current standard).
  • Asymmetric (Public Key): Public encrypts, Private decrypts. RSA (prime factorization), ECC (shorter keys), Diffie-Hellman (secure key exchange).
  • Hashing (One-Way): Fixed-length irreversible digest for Integrity: MD5 (128-bit, broken), SHA-1 (160-bit, deprecated), SHA-256 (256-bit, secure standard).
  • Digital Signature & PKI: Hash encrypted with sender's Private Key → ensures Authentication + Integrity + Non-repudiation. CA issues X.509 SSL/TLS certs.
  • Firewalls & Network Defense: Main types: Packet Filter (L3/L4 stateless), Circuit-Level Gateway (validates TCP handshakes/sessions), Stateful Inspection, Application/Proxy Gateway (L7), and NGFW (DPI + IPS) — Trap: "Client-level firewall" is NOT a firewall class. DMZ isolates public servers.
  • IDS vs IPS & VPN: IDS (passive monitor, alerts on anomalies) vs IPS (inline, actively drops malicious packets). VPN encrypts tunnels via IPsec (ESP/AH; Tunnel vs Transport mode) or SSL/TLS.
  • CERT-In & RBI Reporting: CERT-In (nodal agency under IT Act Sec 70B) mandates reporting listed cyber incidents within 6 hours, 180-day rolling ICT log retention in India, and NTP clock sync. RBI Cyber Security Framework also requires banks/NBFCs to report unusual cyber incidents within 6 hours.

Ch 8: DBMS Architecture, Normalization, SQL & Transactions Core IT Officer

Data Hierarchy, 3-Schema Architecture & Integrity Keys

Hierarchy, 3-Schema & ER Concepts

  • Data Hierarchy (Smallest → Largest): Bit < Byte < Field (Attribute) < Record (Tuple) < Table (Relation) < Database < DBMS. Degree = no. of columns; Cardinality = no. of rows.
  • ANSI-SPARC 3-Schema Architecture: Internal/Physical (storage layout) → Conceptual/Logical (tables, constraints) → External/View (user-specific views).
  • Data Independence: Physical (modify storage without changing logical schema) vs Logical (modify logical schema without breaking external views).
  • ER Notation: Weak Entity (double rectangle, needs owner + partial key), Multi-valued Attribute (double oval), Derived Attribute (dashed oval), M:N relationships require a separate junction table.

Database Keys & Integrity Constraints

  • Super Key: Any attribute set uniquely identifying a tuple. Candidate Key: Minimal Super Key (no proper subset is unique).
  • Primary Key (PK): Selected Candidate Key (Unique + NOT NULL). Alternate Key: Candidate Keys not chosen as PK.
  • Foreign Key (FK) & Referential Integrity: References another table's PK/Unique key; prevents orphaned records (ON DELETE CASCADE / RESTRICT). Composite Key = ≥ 2 attributes.
  • Core Integrity Rules: Entity Integrity (PK must never be NULL) | Domain Integrity (valid data types/CHECK ranges) | Key Uniqueness (UNIQUE permits NULL in SQL).

Normalization (Eliminating Update Anomalies & Redundancy)

3NFIn 2NF + No Transitive Dependency (X → Y → Z)No non-prime → non-prime dependency; lossless & always dependency-preserving
BCNF (3.5NF)For every non-trivial FD X → Y, X is a Super KeyFixes Prime ← Prime anomalies; always lossless join (may not preserve dependencies)

SQL Sub-Languages, Command Traps & Joins

5 SQL Sub-Languages & Query Order

  • DDL (Data Definition): CREATE, ALTER, DROP, TRUNCATE, RENAME (schema-level, auto-commits).
  • DML (Manipulation): INSERT, UPDATE, DELETE • DQL: SELECT.
  • DCL (Control): GRANT, REVOKE • TCL (Transaction): COMMIT, ROLLBACK, SAVEPOINT.
  • Execution Order: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT.
  • WHERE vs HAVING: WHERE filters rows before grouping (no aggregates); HAVING filters groups after GROUP BY.

DELETE vs TRUNCATE vs DROP & Joins

  • DELETE (DML): Supports WHERE, fires triggers, logs undo, rollback possible, keeps structure.
  • TRUNCATE (DDL): Instantly empties all rows, resets auto-increment, no WHERE, keeps schema.
  • DROP (DDL): Removes data + table schema + indexes completely.
  • Joins: INNER (matches only) | LEFT/RIGHT/FULL OUTER (preserves unmatched + NULLs) | CROSS (Cartesian product m × n) | SELF | NATURAL (auto-matches same column names).
  • Wildcards & Set Ops: LIKE (% = 0+ chars, _ = 1 char); UNION deduplicates vs UNION ALL (keeps duplicates, faster).

Transactions, ACID, Concurrency & Data Warehousing

  • ACID Properties: Atomicity (all-or-nothing, Undo/Redo log) | Consistency (constraints preserved) | Isolation (concurrent executions appear serial) | Durability (committed data survives crashes).
  • Transaction States: Active → Partially Committed → Committed (or Failed → Aborted → Terminated).
  • Concurrency Anomalies & Locks: Dirty Read (uncommitted data), Non-Repeatable Read, Phantom Read. Two-Phase Locking (2PL) guarantees Conflict Serializability (Growing phase acquires locks, Shrinking phase releases; Strict 2PL holds exclusive locks until commit to stop cascading aborts). Timestamp protocols (Wait-Die / Wound-Wait) prevent deadlocks.
  • OLTP vs OLAP & Warehousing: OLTP = live banking txns (normalized ER, fast read/write); OLAP = decision analytics (denormalized, cubes: Roll-up, Drill-down, Slice, Dice). Star Schema (single-layer denormalized Dimension tables around Fact table) vs Snowflake Schema (normalized sub-dimensions). ETL = Extract, Transform, Load.

Linear Data Structures, Trees & Graphs

Arrays, Linked Lists, Stacks & Queues

  • Array: Contiguous RAM, O(1) index access, O(n) mid-array insert/delete.
  • Linked List: Dynamic pointer nodes, O(1) head insert/delete, O(n) linear search.
  • Stack (LIFO): Push/Pop/Peek = O(1). Uses: Recursion call stack, Infix → Postfix expression parsing, balanced parentheses, DFS.
  • Queue (FIFO): Enqueue/Dequeue = O(1). Circular Queue reuses freed slots; Priority Queue uses Binary Heap (O(log n) push/pop, O(1) peek). Uses: Spooling, CPU scheduling, BFS.
  • Hash Table: O(1) avg lookup, O(n) worst case. Collisions fixed by Chaining or Open Addressing (Linear/Quadratic probing, Double Hashing).

Trees, Traversals & Graph Algorithms

  • Binary Tree Bounds: Max nodes at height h = 2^(h+1) − 1. Complete Binary Tree fills levels left-to-right (used by Heaps).
  • Traversals: Preorder (Root-L-R, prefix/copy) | Inorder (L-Root-R → Sorted order in a BST) | Postorder (L-R-Root, postfix/delete).
  • Balanced & DB Trees: AVL Tree keeps balance factor |hL − hR| ≤ 1 (LL/RR/LR/RL rotations). B+ Tree (DB indexes) keeps keys in internal nodes and stores all data pointers in linked leaf nodes.
  • Graph Traversal: BFS (Queue, shortest path in unweighted graph) vs DFS (Stack, cycle detection & topological sort), both O(V + E).
  • Shortest Path & MST: Dijkstra (non-negative weights) | Bellman-Ford (negative weights allowed) | Prim's & Kruskal's (Minimum Spanning Tree).

SDLC Models, Design Principles & Software Testing

SDLC Models & Design Metrics

  • Waterfall: Rigid linear phases, heavy documentation, unsuited for changing requirements. Iterative / Prototyping: Early user feedback.
  • Spiral Model (Barry Boehm): Risk-driven iterative cycles (Planning → Risk Analysis → Engineering → Evaluation). V-Model: Maps each dev phase directly to a test phase.
  • Agile & Scrum: Short 1–4 week Sprints, continuous delivery; roles = Product Owner, Scrum Master, Dev Team. RAD = rapid component assembly (60–90 days).
  • Cohesion & Coupling: Good modular software has High Cohesion (intra-module unity; best = Functional Cohesion) and Low Coupling (inter-module independence; best = Data Coupling, worst = Content Coupling).

Verification, Validation & Testing Types

  • Verification vs Validation: Verification = "Are we building the product right?" (static specs/reviews). Validation = "Are we building the right product?" (dynamic execution).
  • 4 Test Levels: Unit (module level) → Integration (Top-Down uses Stubs; Bottom-Up uses Drivers) → System → Acceptance (UAT).
  • Alpha vs Beta Testing: Alpha = at developer's site by internal QA; Beta = at customer/real-user site pre-release.
  • Black-Box vs White-Box: Black-Box tests I/O behavior (Equivalence Partitioning, Boundary Value Analysis). White-Box inspects internal paths (Cyclomatic Complexity V(G) = E − N + 2). Regression Testing re-runs tests after changes.

Object-Oriented Programming (OOPs) Concepts

4 Pillars of OOPs

  • Encapsulation: Bundling data + methods in a class while restricting direct access (private fields + getters/setters).
  • Abstraction: Exposing essential behavior while hiding implementation details (abstract classes / interface).
  • Inheritance: Acquiring parent properties (IS-A relationship: Single, Multilevel, Hierarchical; Java avoids multiple class inheritance via interface).
  • Polymorphism: "One name, many forms" — Compile-time (Method Overloading: same name, different parameter list) vs Runtime (Method Overriding: subclass redefines parent method, dynamic dispatch).

Relationships, Constructors & Modifiers

  • Aggregation vs Composition: Both represent HAS-A. Aggregation is weak (child survives parent deletion, e.g., Dept & Teacher); Composition is strong/PART-OF (child destroyed with parent, e.g., House & Rooms).
  • Constructor & Destructor: Constructor matches class name, has no return type, runs automatically on instantiation. C++ uses ~Class() destructor; Java/Python rely on Garbage Collection.
  • Modifiers: static binds member to class (shared memory); final blocks reassignment, overriding, or subclassing; super accesses parent members.

Programming Languages, Translators, Software & Extensions

Translators & Language Generations

  • Compiler vs Interpreter: Compiler converts entire source code → object/machine code at once, producing fast executables (C, C++). Interpreter translates & executes line-by-line (Python, JS).
  • Hybrid Execution (Java): javac compiles .java → platform-independent bytecode (.class) executed by the JVM.
  • Assembler / Linker / Loader: Assembler translates Assembly → Machine Code; Linker combines object modules & libraries into executable; Loader places executable into RAM.
  • Generations (1GL–5GL): 1GL Binary Machine | 2GL Assembly | 3GL High-Level (C, Java, Python) | 4GL Declarative (SQL) | 5GL AI Logic (Prolog).
